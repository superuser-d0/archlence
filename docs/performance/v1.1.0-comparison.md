# v1.1.0 performance comparison

Environment: Linux, Python 3.14.6. Baseline and final use the same committed
`scripts/benchmark_large_dataset.py` workload. Medians are milliseconds;
negative percentages are faster. Microbenchmark noise is most visible at
1,000 rows, so no broad “faster” claim is made from those values.

| 50,000-row metric | v1.0.1 baseline | v1.1.0 final | Change |
| --- | ---: | ---: | ---: |
| Database startup | 1.388 | 1.282 | -7.64% |
| Dashboard summary | 287.019 | 281.676 | -1.86% |
| Monthly summary | 25.918 | 25.566 | -1.36% |
| Budget summary | 0.147 | 0.149 | +1.36% |
| Insights (365d) | 778.779 | 774.675 | -0.53% |
| Full-dataset decrypt | 290.033 | 289.812 | -0.08% |
| Legacy migration | 6,754.325 | 6,682.943 | -1.06% |
| Backup | 6,186.228 | 5,991.807 | -3.14% |
| Restore | 5,938.589 | 5,727.473 | -3.55% |

At 10,000 rows, dashboard/monthly/insights/decrypt/migration/backup/restore
changes ranged from -0.08% to -2.82%; startup was +4.82% and the sub-millisecond
budget query was +12.75%. These changes are treated as neutral without repeated
cross-machine samples.
